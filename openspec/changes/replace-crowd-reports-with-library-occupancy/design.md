# Design

## Context

See proposal.md for motivation and replacement scope. `CrowdMeter.tsx` mounts only in the authenticated `spaces` view, uses local selected-location state, and fetches relative `/api` URLs. Its CSS already supports three/two/one columns. Express `createApp(store, preview)` embeds anonymous report routes; `index.ts` loads a JSON ReportStore before listening. `server/test/ocr-preview.test.ts` also constructs that store. Campus Explorer independently uses Supabase campus_locations; Prisma has no occupancy model. No checked-in Vercel/Render configuration was found; Vite's development proxy is not production routing.

## Goals / Non-Goals

**Goals:** Reuse the feature component, navigation and styles; isolate provider failures; implement a small, testable integration with native fetch, Maps and CSS/SVG. Live service, details and reporting retirement are essential; historical bars are included when accurately representable, with an explicit unavailable fallback.

**Non-Goals:** Database changes, new runtime dependencies, generalized provider/cache frameworks, shared cache infrastructure, background requests, refresh buttons, weekday selectors, forecasting, live overlays, student reports, photo acquisition as a release prerequisite, or unrelated cleanup.

## Decisions

### 1. Small backend module and fixed catalog

Use `server/src/libraryOccupancy.ts` for catalog, native fetch, normalization and caches; mount two GET routes in app.ts rather than introduce a router/service hierarchy. Expose `GET /api/libraries` and `GET /api/libraries/:id/history`; unknown IDs return 404 before upstream work. Catalog IDs/capacities: 1 North Reading Room 900; 2 Central Reading Room 300; 3 Health Sciences Library 350; 4 Music Library 110; 5 3rd Floor 300. These were verified against the official widget during exploration, not legal or seat capacities.

Live responses contain all five catalog entries with population (nullable), capacity, rounded percentage (nullable), crowd label (nullable), status, retrievedAt (nullable), and source URL. Valid zero remains zero. Apply SBU's rounded, visually capped percentage and boundaries: Low through 50%, Moderate through 80%, Busy above 80%; do not invent an extra Full category. Preserve valid over-capacity counts; estimated remaining occupancy capacity is max(0, capacity - population). Missing/negative/non-finite values are unavailable, never fabricated zeros. Validate actual numeric JSON types rather than coerce null/strings. A finite nonnegative count above 1.5 times capacity is treated as anomalous/unavailable, following the widget's anomaly boundary without copying its zero fallback.

### 2. On-demand cache and failure handling

Create one module/service instance per Express process, with per-ID live entries fresh for five minutes and historical entries fresh for one hour. Deduplicate concurrent misses using in-flight promises cleared on completion/failure. Fetch the five readings concurrently with independent outcomes. Use a five-second upstream abort timeout and basic HTTP/JSON/shape checks; keep the frontend request budget longer. Browser cancellation must not cancel shared upstream work. Cache expiry never initiates work by itself.

On a failed live refresh, return the last good reading as stale only while within 30 minutes of its original retrieval; otherwise return unavailable with nullable metrics. A 30-second failure cooldown prevents immediate repeated upstream attempts. Failures never reset successful retrieval timestamps or freshness. Mark cached live values stale in an already-open view once five minutes elapse; after 30 minutes hide population, percentage, level and remaining-capacity estimates as current values and show unavailable. Use display-only expiry scheduling and re-evaluate age on render/resume without fetching; expiry must apply even without another API response. Backend responses include freshUntil and usableUntil absolute timestamps to support that later frontend behavior. Backend success cache age and frontend age must remain visible. Return no-store HTTP headers for these routes so Express is the only freshness cache. Avoid generalized retry/circuit-breaker infrastructure.

Historical failure returns a history-only unavailable result (or route error handled in its own UI state); do not substitute student data or affect live state. Keep `/api/health` independent of provider availability. Fixed HTTPS upstream, allowlisted IDs and fixed history parameters prevent an open proxy; never forward student tokens/cookies to SBU. Retain anonymous aggregate GET access and the existing authenticated UI boundary.

### 3. Existing component with static amenities and placeholders

Adapt CrowdMeter.tsx/CSS and preserve its export, App.tsx mount and `?view=spaces` navigation. A small `libraryOccupancyApi.ts` adapter and `OccupancyChart.tsx` are sufficient extra frontend modules; do not split every card/detail into separate files. Fetch the live list once per feature opening; reuse it while selecting/backing out of details. Reopening the feature requests Express again, subject to its cache. Remove polling, visibility-triggered requests and explicit refresh controls. Error text instructs users to reopen the feature; no refresh/retry button is required for this scope. Keep request cancellation/generation checks so late responses cannot populate another library.

Static catalog metadata includes amenity text/counts, scope, source URL and optional image credit. Numerical computer counts describe installed workstations, not available/unoccupied computers. Use matching styled placeholders with location names and reserved image aspect ratios; they must not masquerade as real photographs. Display approved photos later without layout redesign.

From the official Places to Study source, numerical amenities are: North 44 computer seats, 700+ outlets, 12 group rooms; Central 46 computer seats, 500+ outlets, 4 collaborative rooms and 6 graduate rooms; Health Sciences 22 workstations and 600+ outlets (library-wide); Music 14 Mac and 5 Dell computer seats and 52 listening-station seats. The source also lists North 600+ seats and Central 242 seats, distinct from occupancy capacity. ID 5 remains 3rd Floor; separately identify Main Stacks facilities (56 small-table seats, 199 study-carrel seats, 4 lounge chairs, 276+ outlets), explicitly noting sensor coverage may differ. Do not infer exclusive sensor coverage or another third-floor identity. Scope library-wide Health Sciences amenities explicitly. No live computer or room availability claims.

### 4. Historical request and bar visualization

The inspected SBU script initializes/resets dayOffset=0 with no observed advancing selector, requests 60-minute/24-bucket histograms, preserves bucket order, and leaves time-window selection to the server. Following focused comparison and user approval, use its official room-specific reference weeks: 52 for IDs 1–3, 48,49,50 for ID 4, and 49,50,51 for ID 5. A small static backend historyWeeks map controls the request and validates echoed metadata; the frontend validates the expected selection for the room. Success cache, in-flight deduplication and failure cooldown keys include room ID and the selection. Preserve the one-hour history TTL, five-second timeout, separate 30-second history failure cooldown and live independence. No runtime widget scraping, duplicate baseline request, client-supplied week override, per-week requests or custom averaging is introduced.

Normalize returned count/hour_num/datetime without sorting by hour or converting timezone-less datetimes to UTC/browser-local instants. Preserve order and window metadata. Prior probes returned 4 PM through 3 PM next day, not a midnight calendar day; combined integer counts matched averages in some buckets and 463 versus arithmetic 463.5 in another. Do not promise exact rounding, sampling semantics, a forecast, or that returned reference dates identify all contributing weeks. A fixed request does not justify a Today/Typical Monday label. Use neutral Historical hourly occupancy wording, explain SBU reference weeks, identify returned first/last hours and the midnight transition, and retain reference timestamps in API metadata/developer documentation. For the approved live comparison only, explicitly assume SBU hour labels are campus-local America/New_York; this is a user-accepted assumption, not a verified provider guarantee, and requires no further timezone investigation.

Timebox focused validation of the returned hour/window interpretation and configured reference-week usability to approximately two hours and genuinely attempt the desired bar chart. Unknown internal rounding, sampling or averaging details alone do not prevent implementation if returned values, sequence and window can be accurately shown with transparent caveats. Only an actual inability to represent the returned data accurately warrants historical-trends-unavailable text and an official source link. Keep the integration and UI independently testable and release the live feature regardless. Do not invent replacement windows, aggregate manually, or silently use zero for missing buckets. A documented deferral closes the release decision, not a claim that the graph was delivered.

For usable history, render lightweight CSS/SVG rounded vertical bars on a constant 0–100% axis using existing burgundy/pink colors. Convert SBU count to percentage using configured capacity without reaggregation; retain enough precision to round only for display. Cap bar height at 100% and disclose actual values above 100% in the tooltip/text. Invalid/missing buckets are gaps. Label a few hours and mark the midnight crossing. Provide hover and tap selection plus keyboard-focusable hourly controls with a persistent readable hour/percentage description; no hover-only information. Support 375px without page overflow. No animation library, weekday selector, live overlay or custom chart framework.

Group 3 review refinement: place the separate Historical hourly occupancy card directly beneath amenities in the desktop right-hand column, stacking on smaller screens. Use compact name/percentage spacing, the subtitle "Find the best place to study based on current library occupancy.", and "View library details →". Remove the student-facing cache-duration text, use "Retrieved" / "Last retrieved" with relative age for per-reading age distinction, and shorten disclaimers while retaining the occupancy-capacity/seat distinction. Replace the global age/unavailability banner with subtle grid-footer fine print; preserve actual request errors and all freshness logic. CSS bars use a roving keyboard tab stop with arrows/Home/End, hover/tap selection, explicit missing × and zero baseline marks. Do not change live timing or add automatic requests.

Investigation outcome: both the original four-week baseline and SBU's official selections returned 24 numeric hourly buckets for every room, from 08:00 to 07:00 next day. The official selections produced prior-year reference dates and materially different counts; these observations do not confirm a seasonality rationale or better predictive accuracy. One adjacent dayOffset request shifted reference dates, not a fixed weekday. The graph is implemented; internal sampling/coverage remains transparently unverified. Use the concise visible line "Historical occupancy based on SBU Libraries’ reference weeks. Not a forecast." Retain one short hover/tap/keyboard and midnight/missing/zero legend. Reference timestamps, room-specific parameters, sampling limitations and timezone uncertainty belong in developer documentation. The collapsed-by-default "About this data" contains only concise reference-week/campus-hour context, the hourly window and midnight/interaction/missing/zero guidance. Do not call the single-week selections a multi-week average. See docs/library-occupancy.md for evidence and response contract. The user confirmed ordinary local npm run dev works without additional certificate configuration; no TLS changes are needed or made.

The final Group 3 comparison refinement is client-only. Pass the selected live DTO and the parent's existing display clock into OccupancyChart; its fetch effect remains keyed solely by library ID. A small pure comparison helper uses Intl.DateTimeFormat with the existing campusZone and hourCycle h23 to match the live retrieval hour to exactly one historical bucket. Use population/capacity * 100 for live (the DTO percentage is rounded/capped) and the history bucket's uncapped percentage. Classify live minus history <= -10 as Less busy than usual, >= +10 as Busier than usual, otherwise About as busy as usual; tolerate only arithmetic floating-point noise at exact boundaries, never classify using display rounding. Hide for non-fresh/expired live data, missing/invalid history, ambiguous hour matches or library mismatch. The existing local clock removes comparison on freshness expiry/resume without requesting data. Render compact green/muted-blue/muted-amber h3 without a supporting sentence immediately beneath the historical h2, with no main-card comparison or live bar overlay. Actual values drive thresholds even though the supporting percentage sentence is removed. Briefly disclose campus-local-hour assumption and SBU reference weeks under About this data. This adds no backend or cache changes, network requests, polling or dependencies.

Final presentation refinement: preserve graph dimensions and burgundy bars; use PLAN YOUR VISIT eyebrow, source "Source: SBU Libraries.", and brief not-a-forecast text. Initial selection uses a unique valid retrieval-campus-hour bucket, otherwise the first; explicit user inspection persists across rerenders. Details show two side-by-side number-first metrics, Current occupancy and Est. remaining capacity, with "Estimated capacity, not guaranteed available seats." Hide configured capacity and redundant full timestamps. Live meters use #397B58 / #BD8B32 / #AD414D without age fading and with readable darker status labels. Main cards retain compact layout; remove Retrieved on opening and separate Older reading labels. ID 5 remains 3rd Floor; its separate amenities card identifies Main Stacks with verified 56 small-table seats, 199 study-carrel seats, 4 lounge chairs and 276+ outlets, and notes that sensor coverage may differ. No exclusive Main Stacks sensor claim or placeholder changes. These presentation decisions supersede earlier UI wording; all backend/expiry/request logic remains unchanged.

### 5. Scope and deployment

Keep relative API calls and current Vercel-to-Render forwarding. Verify dashboard routing, Render plan, actual runtime/start command and process count during implementation; use existing scripts and preserve PORT binding. Process-local caching resets on restarts and duplicates across instances; accept this limitation for the senior project rather than add Redis. A free Render cold start may exceed the frontend budget: retain clear error/reopen behavior and document the observed limitation instead of changing hosting automatically. No deployment or external setting changes are authorized by planning.

## Risks / Trade-offs

- Ambiguous histogram windows/coverage -> focused validation and honest graph omission, never a live-feature blocker.
- Numerical amenities differ from sensor capacity or broader areas -> keep source/scope and distinguish installed facilities from live availability.
- No polling or refresh button -> retrieval age remains visible and stale status advances locally; reopen to request again.
- Photo identity/rights uncertain -> consistent placeholders ship first; record credits/source/license before replacement.
- Upstream outage or cold start -> partial results, bounded stale fallback, timeout and cooldown; independent health and history.

## Migration Plan

Implement backend and UI incrementally on the working branch; add new GET endpoints before switching the frontend. At UI cutover, disable the report POST (404/410 with no write), remove old GET routes, report UI/types/polling, crowd.ts, ReportStore startup load and CROWD_REPORTS_PATH documentation. Update the app factory and OCR test fixture without changing OCR options. Leave saved JSON untouched and unused. Replace obsolete tests; preserve unrelated API errors/statuses and account/privacy behavior. No SQL migration, main-spec sync or historical-change edit is required during implementation.

If deploying separately, keep old routes only during the short backend-first preparation; report submission must be disabled at cutover. Roll back to a compatible university-only build or show Study Spot Finder unavailable; do not silently restore student reporting as fallback. Deployment verification/changes require the implementation-stage scope; do not deploy from this planning task.
